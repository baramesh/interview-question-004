# UIX-PF-01 — พฤติกรรมหน้าสร้างโปรไฟล์

| เหตุการณ์       | เงื่อนไข                    | พฤติกรรม                                                                               |
| --------------- | --------------------------- | -------------------------------------------------------------------------------------- |
| เลือกรูป        | ชนิดและขนาดถูกต้อง          | อ่านเป็น Base64 แสดงตัวอย่างและชื่อไฟล์                                                |
| เลือกรูป        | ชนิดไม่รองรับหรือเกิน 2 MB  | ไม่เก็บค่าและแสดงข้อผิดพลาด                                                            |
| กด Remove       | มีรูปตัวอย่าง               | ล้าง Base64 รูปตัวอย่าง ชื่อไฟล์ และค่า file input                                     |
| เปิดหน้า        | API ข้อมูลหลักสำเร็จ        | เติมรายการอาชีพด้วย `name` และเก็บ `code` เป็นค่าที่เลือก                              |
| เปิดหน้า        | API ข้อมูลหลักล้มเหลว       | แสดงข้อผิดพลาดการโหลดอาชีพและไม่สร้างรายการสำรองใน Client                              |
| กดปุ่มปฏิทิน    | ช่องวันเกิดพร้อมใช้งาน      | เปิด Angular Material Datepicker โดยไม่เรียกตัวเลือกวันที่ดั้งเดิมของเบราว์เซอร์       |
| เลือกวันเกิด    | วันที่ไม่เกินเมื่อวาน       | แสดงค่า `DD/MM/YYYY` และเก็บเป็น `Date` ผ่าน date-fns adapter จนกว่าจะสร้าง payload    |
| กด Save profile | แบบฟอร์มผิด                 | ทำเครื่องหมายทุกฟิลด์และไม่เรียก API                                                   |
| กด Save profile | แบบฟอร์มถูก                 | แปลงวันเกิดเป็น `DD/MM/YYYY`, ปิดปุ่ม แสดงตัวหมุน และเรียก API โดยส่ง `occupationCode` |
| API สำเร็จ      | ได้ `201`                   | แสดง Angular Material Toast `save data success · ID: {id}` 5 วินาทีแล้วล้างแบบฟอร์ม |
| API ล้มเหลว     | ไม่ได้ `201`                | แสดง Toast ข้อผิดพลาด 7 วินาที เปิดปุ่ม และคงข้อมูล                                             |
| กด Clear        | ทุก state ที่ไม่กำลังบันทึก | ล้างข้อมูล รูป ชื่อไฟล์ และปิด Toast ที่กำลังแสดง                                             |

## ลำดับการกรอก

ผู้ใช้กรอกตามหมวด `Profile photo → Personal details → Contact details → Professional details` โดยทุกหมวดอยู่ในแบบฟอร์มเดียว การแบ่งหมวดไม่มีผลต่อ payload หรือ endpoint
